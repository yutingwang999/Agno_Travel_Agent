# Proposal

## Why

Requests can only be made through a five-field form, so the planner never sees what a traveller would actually say ("We're taking our two kids, 6 and 9, to Sydney for 3 days, mid-range budget"), and the evaluation dataset's `utterance` and `gold_slots` have no system to measure: slot extraction has been reported as "N/A, no request parser" since `build-evaluation-harness`. Roadmap item 3 asks for parsing what the user says into a request object; `rebuild-rag` settled the retrieval side (every request retrieves), so the request is the next part to make real.

This is the first of two changes for roadmap item 3. It adds the parser and a free-text way in; `clarify-requests` will follow with clarifying questions for contradictory or unfeasible requests (one round, with choices) and a fallback rule after that round.

## What Changes

- New `POST /parse`: takes one free-text sentence and returns a request object with the form's fields (`destination`, `trip_length`, `budget`, `travel_style`, `max_daily_budget_aud`, `notes`), the parsed `preferences`, and the `assumptions` made for missing fields. It makes one LLM call with structured output (`gemini-3.1-flash-lite`); the prompt is a versioned template in the database.
- Missing fields: `budget` defaults to `moderate` and `travel_style` to a general default, each listed in `assumptions` (generated by code, not by the model); a missing `destination` or `trip_length` is left empty for the user to fill in. `notes` holds only the details the other fields cannot express.
- The existing guards apply to the sentence and the parsed destination: prompt injection (`input_rejected`) and destinations outside Australia (`destination_out_of_scope`, with the place list's canonical name). A sentence that is not a travel request is refused with a new reason code, `not_a_travel_request`.
- Frontend: two ways in, "Describe your trip" (free text) and the form. The free-text way fills in the form from `/parse`, shows the assumptions and highlights empty required fields; the user reviews and edits, then generates as today.
- `POST /generate` and the workflow are unchanged; category matching (`cag_match`) stays as it is.
- Evaluation: the harness can evaluate the free-text path (send `utterance` to `/parse`, then generate from the parsed form), report slot extraction accuracy against `gold_slots`, field agreement with each entry's `form`, parser latency and cost, and count a parse that leaves a required field empty as an observed `clarify`. Both paths are run on the same entries and compared in `docs/experiments.md`.

## Capabilities

### New Capabilities
- `request-parsing`: turning a free-text request into a structured request object: the parse endpoint, the request object and its defaults and assumptions, the guards and refusals at parse time, the parser prompt, and the frontend's free-text way in.

### Modified Capabilities
- `travel-workflow`: the guard rejection body gains the reason code `not_a_travel_request`.
- `evaluation-harness`: the free-text path can be evaluated; slot extraction accuracy is defined per slot, including how preferences are matched; field agreement and parser latency and cost are reported; a parse leaving `destination` or `trip_length` empty is observed as `clarify`, which replaces "Clarify expectations" for those entries.

## Impact

- **API**: new public endpoint `POST /parse` and a new guard reason code; `POST /generate` unchanged.
- **Code**: a parser module and endpoint in `src/app/`; the guard code reused from `harden-workflow-guardrails`; a new prompt template key seeded by `scripts/seed.py`; the frontend `src/app/static/index.html`.
- **Evaluation**: `src/evaluation/` (runner, behaviour, metrics), `scripts/eval_run.py`, new configs; `docs/evaluation.md`, `docs/api.md`, `docs/experiments.md`; no dataset changes are expected.
- **Cost**: one extra `flash-lite` call per free-text request, before generation; the form path costs the same as today.
- **Docs and planning**: `docs/roadmap.md` (item 3 split into `parse-requests` and `clarify-requests`; dropping the category presets recorded as a later experiment).
